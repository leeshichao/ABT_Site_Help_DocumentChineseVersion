BACnet/SC Hub

BACnet/SC 逻辑网络架构以集线器为中心，集线器充当所有其他 BACnet/SC 端点设备（节点）连接的中心组件。每个 BACnet/SC 网络必须至少有一个活动集线器 - 主集线器，该集线器必须始终可访问。 BACnet/SC 网络上除活动集线器之外的所有设备都是节点。集线器最好在嵌入式设备上实现，例如系统控制器，这些设备被设计为具有故障恢复能力，并且功能强大，足以支持许多同时节点连接以及不同 BACnet 数据链路之间的 BACnet 路由，同时还执行其作为楼宇自动化控制器的任务。任何支持集线器功能的设备均属于设备的 PICS 中指示的 BACnet Secure Connect Hub (B-SCHUB) 标准化设备配置文件以及设备还支持的任何其他标准化设备配置文件，并支持安全连接、（附件 YY）链路层选项和网络管理-安全连接集线器-B (NM-SCH-B) BIBB。

虽然在搜索 BTL 列表时 B-SCHUB 设备配置文件清楚地指示 BACnet/SC 集线器设备，但没有设备配置文件明确指示 BACnet/SC 节点设备。从设备配置文件中识别节点设备的唯一方法是检查附件 YY 是否支持 BACnet/SC 数据链路层。

BACnet/SC 网络（由网络号和端口号定义）上一次只能有一个活动集线器。强烈建议使用冗余集线器实施 BACnet/SC 网络以避免停机。故障转移集线器可以是网络上具有 BACnet/SC 集线器功能的另一个系统控制器。任何具有集线器功能的设备本质上也是一个节点。当主集线器处于活动状态时，故障转移集线器将充当节点，直到出现无法访问主集线器的情况为止。一旦发生这种情况，节点就会配置为寻找故障转移中心并连接到它。节点切换到故障转移集线器，并在最小程度的中断后继续通信。

由于任何具有集线器功能的设备本质上也是一个节点，因此一旦网络上安装了两个推荐的集线器（主集线器和故障转移集线器），具有集线器功能的同一设备就可以用作控制器，在出于集线器功能以外的原因需要时充当 BACnet/SC 节点。

BACnet/SC 逻辑网络架构是对 BACnet/IP 的改进，如果 BACnet 系统包含多个 IP 子网，则 BACnet/IP 使用 UDP 广播和 BACnet 广播管理设备 (BBMDs)。从历史上看，由于底层 IP 网络行为的潜在深远影响，BBMDs 在大型系统中配置一直是一个挑战。 BACnet/SC 网络完全独立于底层 IP 网络结构。在极端的实施中，所有设备（节点和集线器）都可以任意分散到项目周围的不同 IP 网络中。只要节点可以到达其集线器，BACnet/SC 通信就会正常工作。主集线器和故障转移集线器的节点必须知道它们。这需要集线器的静态 IP 地址或完全限定域名 (FQDN)。 FQDN 需要一个工作域名系统 (DNS) 在工程和调试阶段才能正常运行。如果要为此 FQDN 生成证书，则该证书必须由官方且受信任的证书颁发机构创建。

BACnet/SC. 不需要 BACnet 广播管理设备 (BBMDs)，如果网络由混合 BACnet 网段组成，则 BACnet/IP 网络仅需要 BBMDs。一旦 BACnet/IP 设备到达 BACnet/IP 到 BACnet/SC 路由器，并在该连接点路由到 BACnet/SC，路由的 BACnet/SC 网络上就不再需要 BBMDs – 集线器可以跨子网将消息传播到节点。 BACnet/SC 中的连接是出站连接（类似于本地 Web 浏览器到 Internet 上服务器的连接）。节点发起与集线器的连接。这是有意为之的，使得 BACnet/SC 非常 IT 友好，特别是在 IP 微分段用例中，它被用作网络安全技术，使网络架构师能够将网络逻辑地划分为不同的安全分段，直至各个工作负载级别，然后定义安全控制并为每个独特的分段提供服务。
