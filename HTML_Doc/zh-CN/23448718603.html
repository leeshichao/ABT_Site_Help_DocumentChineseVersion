FAQ BACnet/SC

 

 

问题：

  • Can I commission a network directly as BACnet/SC?
  • Can I subsequently put a device into operation directly as BACnet/SC?

答案：没有

BACnet/SC 网络必须始终首先作为 IP 网络进行调试。在现有 BACnet/SC 网络中，新设备或要更换的设备必须首先作为 IP 设备进行调试。请注意，在此调试时该网络内存在安全漏洞。

问题：

如果我激活了会发生什么Disable BACnet/IPBACnet/SC 网络中设备的选项？

回答：

所有设备进行通信并保证数据交换。但是，启用 IP 的设备存在安全漏洞。因此，该网络不再是保证 100% 安全的 BACnet/SC 网络。

问题：

我可以仅将系统的一部分配置为 BACnet/SC 网络吗？

回答：

对 BACnet/SC 网络的更改可以分阶段完成。但是，建议始终转换枢纽或楼层内的整个子区域。未转换的区域仍然存在遭受黑客攻击的潜在风险。

问题：

当 ABT 站点是内部 /self-signed CA 时，ABT 站点项目设置中 ABT 站点用于自动创建根证书的唯一（且永久 - 是否有永久标识符）标识符是什么？

回答：

所有 ABT 站点项目都有所谓的唯一 UUID （通用唯一标识符），该标识符在创建时设置。根证书与其绑定，也意味着证书始终绑定到项目而不是特定的 ABT 站点安装。

问题：

当 ABT 站点是内部 /self-signed CA 时，ABT 站点用于创建操作证书的嵌入式设备的唯一且永久标识符（除了设备序列号和可能的 NIC MAC 地址）是什么？

回答：

使用的唯一标识符是序列号，因此证书被颁发给特定设备并且无法转移。该证书还包含 DHCP 设备的“FullyQualifiedDomainName”（即域 + 主机名），或非 DHCP 设备的 IP 地址。

问题：

  • What device configuration changes (which objects/properties) would require new operational certificates to be generated for embedded devices (PXC, DXR, etc.,)? Changing network config from IP to DNS?
  • Device name property?

回答：

如前所述，使用序列号和 FQDN/IP。当您重新配置网络（以便主机名和 /or IP 更改）时，或者当您必须更换损坏的控制器时，就会需要重新颁发证书。

问题：

  • Are BACnet/SC certificates stored as part of the ABT Site project?
  • If I archive an entire project, are the certificates included in the archive?
  • Can that archive be opened by another ABT Site installation?

答：是的。

证书是项目的一部分，它们将随项目一起转移。只要您拥有所需的凭据，您就可以使用另一个 ABT 站点安装打开该项目。它们当然是加密的，因此除非您有用户名和密码，否则您无法访问它们。

问题：

  • When a new technician needs access to a site which has been configured for BACnet/SC and BACnet/IP UDP ports are all closed, how do they get access when ABT Site is the internal/self-signed CA?
  • Do they need a copy of the entire archived ABT Site project?
  • Can they simply get an export of the Root certificate only from the original project and import into their ABT Site installation?

回答：

出于安全原因，无法导出根目录。有两种方法可以访问这些设备。 Pack and go 将提供所需的操作证书，因为 pack and go 也受密码保护。

第二种方法是从第二个 ABT 安装发出证书签名请求。然后，原始项目可以对其进行签名并返回签名的操作证书，就像我们内部为控制器所做的那样。

问题：

  • How securely are BACnet/SC certificates stored in ABT Site project folders?
  • Are they in an encrypted folder?
  • What would have to be done to further harden ABT Site in this use case?

Note：这是一个针对内部 /self-signed 用例的问题，当 ABT 站点位于 IT/building 运营办公室时。 ABT 站点安装可以通过在计算机上使用强登录凭据、ABT 站点项目本身的强密码以及限制对 ABT 站点所在计算机所在房间的物理访问来“强化”。

回答：

一切确实都经过加密，并且该解决方案已经过审查并与西门子安全标准同步。对于证书存储，我们使用与保护数据访问控制器和项目本身相同的机制（例如，保护 username/password 数据的机制）。

问题：

  • Do BACnet/SC certificates work with pack and go/pack and return?
  • How are certificates handled with pack and go/pack and return workflows?

回答：

是的，它有效。

该包包含根证书和使用导出设备创建的所有操作证书。您可以创建新设备，为其创建证书并在需要时返回。由于证书管理，工作流程不会发生任何变化。在打包和返回时，所有数据都将被合并回来，除非您对根证书进行了更改，否则这将被忽略，因为否则会弄乱现有数据。

问题：

是否可以从设备中删除有效的证书？

回答：

必须清除设备并分配假证书。
参见章节Configure and download并阅读“清除设备和清除应用程序命令所需的其他信息”部分。
